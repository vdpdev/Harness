# Harness Self-Development Rules

> This file contains rules and context **only for developing the harness itself**.
> It does NOT ship in the scaffolded project and does NOT apply to end users.

## Project Goal

Harness is a TypeScript project development boilerplate for agent-native workflows —
ticket-first development, repo health checks, local CI pipeline, agent skills, and
automated verification.

## Fresh-project flexibility (read first)

This is a **fresh, pre-1.0 project with no external users to keep backwards-compatible
with**. Optimize for the project's goal, not for stability of the past. That means:

- **Anything may change** — any process, any file format, any API surface, any convention,
  any script, any doc — as long as the change is aligned with the project goal.
- **Do not preserve legacy for its own sake.**
- **No deprecation cycles required.** Remove dead paths, rename things, restructure stores,
  and delete files when it makes the project cleaner.
- The only hard constraint is **alignment with the project goal** (see **Project Goal** above).
- Still record intent as a ticket (Ticket-First below) and keep changes complete and verified.
- **Never create or maintain a CHANGELOG.** Tickets in `tickets.json` are the authoritative
  change history.

## Publishing

The harness is published to npm via GitHub Actions using **OpenID Connect (OIDC) provenance**.
No `NPM_TOKEN` secret is needed — the trust relationship between the npm package and the
GitHub repository handles authentication. The `--provenance` flag in `.github/workflows/publish.yml`
generates a signed provenance attestation automatically.

Do NOT add `NODE_AUTH_TOKEN` or similar secrets to the publish workflow — it is not needed
and would be the wrong approach.

## Intentional design decisions (do NOT file tickets for these)

The following behaviors are **by design**, not bugs. Do not re-file them as issues.

- **postinstall only warns, never blocks** (`scripts/utils/check-package-manager.ts`):
  Detects wrong package manager and prints a warning but exits 0. This is intentional —
  see CONTRIBUTING.md:16 ("the postinstall script only warns"). Blocking would break
  `npx` usage and CI pipelines that use npm.

- **tsconfig excludes test/ from typecheck** (`tsconfig.json`):
  `rootDir: ./src` and `include: ["src/**/*.ts"]` are correct. This is a scaffold project —
  test files are written by the user after scaffolding and depend on `src/` which is a
  placeholder. Typechecking user-written tests against an empty `src/` is not meaningful.

- **.nvmrc pins 26, engines says >=26** (`.nvmrc` + `package.json`):
  `.nvmrc` is for local development convenience (use Node 26). `engines` declares minimum
  compatibility for consumers (works on 26+). These serve different audiences and intentionally
  differ.

- **No main/exports/types in package.json**:
  This is a CLI scaffolder, not a library. You consume it via `npx @vdpdev/harness <name>`,
  not via `import`. `src/index.ts` is a placeholder comment for the user to replace after
  scaffolding. No library entry points are needed.

- **pnpm-workspace.yaml lists '.' as a workspace package**:
  This is required for pnpm to manage the root package. It is standard for single-package
  repos that use pnpm workspaces.

- **.env.example is empty**:
  The project uses no environment variables. The file exists as a signal that env vars may
  be needed in forked projects. It is a harmless placeholder.

## Available skills (repo-local, cross-CLI)

- **`review-project`** (`.agents/skills/review-project/SKILL.md`): thorough first-impression /
  end-user gap review of the whole project — finds gaps, bugs, packaging/docs problems and consumer
  risks, then turns every finding into a ticket in `tickets.json`.

- **`harden-tests`** (`.agents/skills/harden-tests/SKILL.md`): Sword-vs-Shield systematic, resumable
  per-test hardening harness. Enumerates every test file, classifies each as **sword** (asserts
  product behavior) or **shield** (guards quality), and improves each test. Driven by a resumable
  queue (`scripts/jsonstore-layers/test-coverage.ts`, a thin layer over `scripts/jsonstore-layers/jsonstore.ts`).

- **`implement`** (`.agents/skills/implement/SKILL.md`): Autonomous ticket-driven work session starter.
  Picks the next actionable ticket, works on decision-free tickets first, then surfaces decision-required
  tickets with options.

- **`no-assumption`** (`.agents/skills/no-assumption/SKILL.md`): Stop and ask when certainty is below 95%.
  For discovery/planning phases.

- **`no-blind-implement`** (`.agents/skills/no-blind-implement/SKILL.md`): Never implement blindly.
  Question the plan, surface missing assumptions, identify scope gaps before writing code.

- **`progressive-confidence`** (`.agents/skills/progressive-confidence/SKILL.md`): Staff-level engineering
  discovery before design or implementation. For non-trivial features.

- **`suggest`** (`.agents/skills/suggest/SKILL.md`): Brainstorm options before committing. Manual skill.

- **`refactor-split`** (`.agents/skills/refactor-split/SKILL.md`): Automated function extraction from
  monolithic .ts files into per-barrel subdirectories. After splitting, auto-formats, lint-fixes,
  runs full CI to validate, fixes any failures, and commits the clean result.
